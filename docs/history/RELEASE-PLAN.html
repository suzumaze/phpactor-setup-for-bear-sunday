公開前にクリアしておきたいこと

Kimi（外部の意見）の指摘です。

最低限「READMEに明確なInstall手順と『phpactor公式はプロジェクト依存を推奨しないが、技術的制約でこうなっている』旨の注記」を入れること。テストは主要な規約解釈のパターン（例：リソースクラス名→ファイルパス変換）をカバーする自動テストがあれば十分。サポート体制は「個人の趣味プロジェクトのためベストエフォート」と明記して期待値を下げる。

整理すると3点です。

  • 正直な開示。 phpactor自身が「プロジェクト依存として入れる想定ではない」と明言しているのに、技術的な制約でその逆をしている——この事情をREADMEに隠さず書く
  • テストの網羅性は「主要な規約パターンを押さえていれば十分」で、完璧を目指さなくてよい
  • サポート体制の期待値を下げる。「個人の趣味プロジェクト、ベストエフォート」と明記する

見落としがちなリスク

phpactor本体のバージョンアップでExtensionクラスのインターフェースが変わり、BEAR.Lspが動かなくなるリスク（依存バージョンは厳密に指定する）。また「グローバルインストール方式」が動作確認済みでも、Windows/Mac/Linux環境差分やphpactorのキャッシュ競合で壊れる可能性があるため、手順は環境別に検証しておく。
特に注意

グローバルインストール方式は、今のところこの1台のMacでしか検証していません。Windows・Linuxでの動作は未確認です。公開する前に、少なくとも1つは別の環境で試す価値があります。
